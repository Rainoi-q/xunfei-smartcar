# 分支与协作规范

## 一、分支模型

| 分支 | 谁用 | 规则 |
|---|---|---|
| `main` | 全组 | 随时可编译、可运行。**只能通过合并进入，禁止直接提交**（第一周可宽松执行） |
| `feat/a-*` | A | 例：`feat/a-mission`、`feat/a-voice` |
| `feat/b-*` | B | 例：`feat/b-vision`、`feat/b-ocr` |
| `feat/c-*` | C | 例：`feat/c-control`、`feat/c-parking` |
| `feat/d-*` | D | 例：`feat/d-voice`、`feat/d-simulation` |

### 日常流程

```bash
# 1. 每天开工前先同步
git checkout main
git pull

# 2. 回到自己的分支（第一次从 main 建）
git checkout -b feat/b-vision
git merge main          # 已有分支则合并最新 main

# 3. 写代码，随时提交
git add -A
git commit -m "[④] 二维码解析支持多字段"

# 4. 收工前必须推送
git push -u origin feat/b-vision
```

### 合并到 main

由 A 执行（或自行发起 Pull Request）：

```bash
git checkout main
git pull
git merge --no-ff feat/b-vision
git push
```

冲突由改动方负责解决。

## 二、提交信息规范

```
[功能编号] 简述
```

| 前缀 | 用途 |
|---|---|
| `[⑫]` | 巡线 |
| `[⑪]` | 避障 |
| `[⑩]` | 红绿灯 |
| `[④]` | 二维码 |
| `[⑤]` | OCR |
| `[⑥]` `[⑦]` | 光照 / 曝光 |
| `[⑧]` | 货物识别搬运 |
| `[⑨]` | 定点泊车投递 |
| `[①]` `[②]` `[③]` | 语音 / 多指令 / 语义 |
| `[⑬]` | 路径规划 |
| `[⑭]` | 仿真 |
| `[infra]` | 架构、launch、参数 |
| `[docs]` | 文档 |
| `[fix]` | 修复 |

示例：

```
[⑩] 红绿灯识别增加面积过滤，暗光下降噪
[infra] bringup 增加 use_hardware 开关
[docs] 补充 TaskPlan 使用示例
[fix] 修复巡线在直角弯脱线
```

## 三、仓库纪律

1. **禁止提交编译产物**：`build/`、`install/`、`log/` 已在 `.gitignore` 中
2. **禁止提交大文件**：视频原始素材放网盘，仓库只放链接和成品
3. **禁止 force push 到 main**
4. **每天收工前 push**，不要攒一周
5. **改接口先说明**，见 `docs/接口文档.md` 顶部声明

---

## 四、代码风格

- Python 遵循 PEP8，缩进 4 空格
- 节点文件结构统一：`__init__.py` + `node.py`（含 `main()`）
- 每个节点必须有模块级 docstring：输入 topic、输出 topic、参数说明
- 所有可调参数从 yaml 读，不写死
- 日志用 `self.get_logger().info()`，不用 `print()`

---

## 五、每日站会（10分钟）

固定时间，每人回答三个问题：

1. 昨天完成了什么
2. 今天计划做什么
3. 卡在哪里

**卡住超过 2 小时必须上报**，不允许一个人闷头 debug 一整天。

## 六、每周日复盘

对照《方案一》第八节的周里程碑逐项打勾，更新 `docs/功能清单.md`。

未达成的项要当场决定：延期、降低标准、还是放弃。
