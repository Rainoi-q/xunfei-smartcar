## 4. 跑任务

### 4.1 全自动（推荐演示流程）

1. 车放在巡线起点，确认 HUD 上 `LINE` 有偏移、`mode` 为 `line`；
2. 车沿着线走，**镜头正对投递点二维码**时，`/perception/qr_payload` 出现 JSON；
3. `mission_manager` 自动开始任务（`/mission/state` → `NAVIGATING`）：
   - 有 nav2：按二维码里的 `destination` 选路线，nav2 开到投递点附近；
   - 没有 nav2（仿真）：直接进入 `DOCKING`；
4. 泊车节点接管 `/cmd_vel_park`，慢速对正二维码、靠近到 `target_distance` 后停稳 1.5 s；
5. `/mission/state` → `DONE`，车停住不动。

### 4.2 手动发任务

```bash
# 用路线名（waypoints.yaml 里 routes 的名字）
ros2 topic pub --once /mission/start std_msgs/msg/String "{data: deliver_3}"

# 用二维码 destination（会经过 destinations.yaml 别名）
ros2 topic pub --once /mission/start std_msgs/msg/String "{data: door_3}"

# 用完整 JSON（order 信息会进 /mission/event，PPT 截图很好看）
ros2 topic pub --once /mission/start std_msgs/msg/String \
  "{data: '{\"destination\":\"door_3\",\"order_id\":\"A03\"}'}"

# 复位：任务结束后想再跑一次必须先复位；复位只回 IDLE 并停车，不会自动恢复巡线
ros2 topic pub --once /mission/reset std_msgs/msg/Bool "{data: true}"

# 要重新开始巡线演示时，显式打开巡线
ros2 topic pub --once /control/line_enable std_msgs/msg/Bool "{data: true}"
```

观察：

```bash
ros2 topic echo /mission/state       # IDLE / NAVIGATING / DOCKING / DONE / FAILED
ros2 topic echo /mission/event       # 含订单字段的迁移事件
ros2 topic echo /control/parking_state
ros2 topic echo /mission/nav_status
```

### 4.3 安全机制（答辩可以讲）

- **唯一 `/cmd_vel` 发布者**：巡线和泊车只发 `/cmd_vel_line`、`/cmd_vel_park`，
  由 `cmd_vel_arbiter` 统一仲裁；任何来源断流 0.5 s 自动落回 0。
- **导航阶段让权**：`mission_manager` 发 `/control/nav_active=true` 时，仲裁器
  不输出速度，`/cmd_vel` 完全交给 nav2；避障急停仍然有效。
- **任务期间禁止抢方向盘**：任务一开始就发 `/control/line_enable=false` 暂停巡线，
  DONE/FAILED 后保持暂停；`/mission/reset` 也只停车，要恢复巡线必须手动发
  `/control/line_enable true`。
- **节点退出发零速**：仲裁器、巡线节点在 `destroy_node` 里补发一帧零速度。

### 4.4 急停

```bash
# 1) 软停：停掉任务并停巡线
ros2 topic pub --once /mission/reset std_msgs/msg/Bool "{data: true}"

# 2) 直接掐巡线开关
ros2 topic pub --once /control/line_enable std_msgs/msg/Bool "{data: false}"

# 3) 兜底：Ctrl-C 掉 bringup（仲裁器退出时会发零速）
#    但底盘驱动仍在，厂家遥控器/急停开关才是最后手段
```

## 5. 参数与现场标定

**只改** `src/smartcar_bringup/config/params.yaml`，改完重新 `colcon build` 或
（更快的）用 `ros2 param set` 临时试：

### 5.1 ⑫ 巡线

| 参数 | 位置 | 说明 |
|---|---|---|
| `threshold` | `vision_detect` | 白底黑线=100 左右；先看 `/perception/debug_image` 二值图 |
| `invert` | `vision_detect` | 黑底白线改 `true` |
| `roi_top` | `vision_detect` | 0.60=只看画面下 40% |
| `kp/ki/kd`、`target_speed` | `line_follower` | 先调 kp，再少量加 kd；`target_speed` 建议先 0.15 再往上加 |

```bash
ros2 param set /vision_detect threshold 110
ros2 param set /line_follower target_speed 0.20
ros2 param set /line_follower kp 1.0
```

### 5.2 ⑨ 泊车

| 参数 | 说明 |
|---|---|
| `target_distance` | **有深度就靠它**：停稳时相机到二维码板的前向距离（米）。Astra 正常 0.4~0.6 用 0.45 |
| `target_height_ratio` | 没有深度时的后备：二维码高度 / 画面高度。把车放到"合适距离"手动读一次 `parking_state` 里的 `height_ratio`，填进来 |
| `approach_speed` | 靠近段速度，0.12~0.18 比较稳 |
| `timeout` | 找不到码的超时（默认 35 s） |

视频/仿真里的正交相机用 1.0 m 停，实车用 0.45 m——**不要**把仿真值抄到实车。

### 5.3 ⑪ 避障

| 参数 | 说明 |
|---|---|
| `stop_distance` | 正前方雷达距离小于它 → 急停（默认 0.35） |
| `slow_distance` | 小于它 → 按比例减速 + 转向偏置（默认 0.85） |
| `depth_stop_distance` | 深度图中央区域小于它 → 急停（默认 0.20） |

### 5.4 ⑥⑦ 光照与曝光

```bash
ros2 topic echo /camera/brightness     # 0暗 1中 2亮
ros2 topic echo /lighting/status       # 当前曝光值
```

`lighting_adaptor` 默认用 **v4l2 直接调 UVC 相机**（`exposure_backend: v4l2`）。
如果实车用的是厂家 Astra（曝光由厂家节点管），把 `exposure_backend` 改成 `none`
（只做光照判断，不动曝光），⑥ 仍然得分，⑦ 交给厂家自动曝光。

### 5.5 ⑤ OCR

```bash
ros2 topic pub --once /perception/ocr_request std_msgs/msg/String "{data: now}"
ros2 topic echo /perception/ocr_text
ros2 run rqt_image_view rqt_image_view /perception/ocr_debug_image
```

只识别画面中上部 ROI（默认 y 10%~70%），免得把地面文字/线路当地标。

## 6. 录制 / 修改航点（⑬）

`config/waypoints.yaml` 里现在是**仿真用的占位点**，实车必须重新录。

1. 启动厂家建图/定位，让 AMCL 收敛（`ros2 topic echo /amcl_pose` 有稳定输出）；
2. 遥控车到投递点，车头朝向"二维码在正前方"的方向；
3. 另开终端录制：

```bash
ros2 run waypoint_nav record_waypoint --ros-args \
  -p waypoints_file:=$HOME/smartcar_ws/src/smartcar_bringup/config/waypoints.yaml
```

4. 每到一个点发一次名字：

```bash
ros2 topic pub --once /mission/record_waypoint std_msgs/msg/String "{data: door_3}"
```

5. 录完手动打开 YAML，把 `routes:` 里的顺序按场地调整。

> 录制器会**重写整个文件**（丢掉注释）。先 `cp waypoints.yaml waypoints.yaml.bak`。

`config/destinations.yaml` 负责把二维码里的 `destination` 映射到路线名：

```yaml
aliases:
  door_3: deliver_3
  door_1: deliver_1
```

## 8. 虚拟仿真（⑭）

### 8.1 一键跑

```bash
source /opt/ros/humble/setup.bash
source ~/smartcar_ws/install/setup.bash
ros2 launch smartcar_bringup sim.launch.py start_web_video:=true
```

- 仿真车从 `(0.9, 1.0)` 出发，自动沿黑线走；
- 靠近终点看到二维码，自动进入泊车，停到距板 1.0 m（正交相机标定值）；
- 没有 nav2，所以任务直接从 `IDLE` 跳到 `DOCKING`（`skip_navigation: true`）；
- **演示循环**：`params_sim.yaml` 里 `virtual_sim.auto_loop: true`，任务 DONE/FAILED 后
  等 6 秒自动复位（仿真车 + 任务状态机 + 巡线），再跑下一轮，网页上一直是活动的。
  想停在结果上就 `ros2 param set /virtual_sim auto_loop false`。

> 仿真和实车不同的参数（`skip_navigation`、泊车 1.0 m 标定）写在
> `config/params_sim.yaml` 的**具名段**里，由 `sim.launch.py` 作为第二个
> params 文件传入。不要在 launch 里用 dict 覆盖：那会生成 `/**` 通配段，
> 而 ROS 2 规则是"命名空间更具体者优先"，通配段永远压不过 `params.yaml`
> 里的 `parking:` / `mission_manager:` 具名段。

看画面：

```
http://<车IP>:8080/stream?topic=/hud/image
```

### 8.2 仿真里常用命令

```bash
ros2 topic echo /sim/pose
ros2 topic pub --once /sim/reset std_msgs/msg/Bool "{data: true}"
ros2 topic echo /mission/state
```

### 8.3 仿真世界长什么样

- 6 m × 6 m 场地，四周有墙，两个圆形障碍（避开巡线路径）；
- S 形巡线路径，终点 `(4.6, 4.4)` 朝 45°，二维码板在正前方 1.2 m；
- 相机是"俯视前向裁剪"，**不是透视**（简化），但输出格式/话题/左右方向与实车一致；
- 深度图按射线遮挡计算，雷达 360 线——避障逻辑与实车同一份代码；
- 仿真二维码板做成 0.7 m，是为了在 640×480 下每个模块还有 ~6 像素、pyzbar 能解；
  实车打印 150~200 mm 即可，不需要照抄 0.7 m。

## 10. 常见问题

| 现象 | 先查 | 解决 |
|---|---|---|
| 车完全不动 | `ros2 topic echo /cmd_vel` 有没有 20Hz | 仲裁器没起 / `enable:=false`；底盘驱动没起 |
| HUD 有偏移但车不动 | `/control/arbiter_state` 的 `mode` | `mode=nav` 说明 nav_active 卡住（任务节点被杀过），发 `/control/nav_active false` 或重启仲裁器 |
| 巡线方向反 | `debug_image` 里线在画面哪边、`/perception/line` 正负 | 颜色反了先改 `invert`；若线在画面右侧但 offset 为负（相机镜像/倒装），临时把 `line_follower.kp` 取负纠正，并在问题清单里登记 |
| 二维码读不到 | `ros2 topic echo /perception/qr_payload` | 打印太小（≥120 mm）、反光、`libzbar0` 没装；斜着放（20~45°）时 zbar 直接解不出，`vision_detect`/`parking` 会自动按 `qr_retry_angles` 补转重试；太斜还是不行就调大该列表 |
| 仿真终端一直没输出、任务停在 IDLE | `ros2 topic echo /mission/status`；`ros2 param get /mission_manager skip_navigation` | 终端 2 不是空的：`/mission/state` 只在状态变化时发，日常看 `status`（1 Hz）。若 `skip_navigation=false`，检查 `config/params_sim.yaml` 是否被 `sim.launch.py` 加载 |
| 仿真像慢动作 / 相机只有几帧每秒 | `/tmp/sim*.log` 里有无 `SIM STATS`（`debug_stats:=true` 打开） | 发图像前务必把 `Image.data` 赋成 `array.array('B', ...)`，别赋 `bytes`/`list`：rclpy 会逐字节校验，921600 字节要 0.7 s |
| 浏览器打开 HUD 一直转圈 | `curl -s -m 5 'http://localhost:8080/stream?topic=/hud/image' \| wc -c`（几万字节以上才算有帧） | 发布端 QoS 必须 **RELIABLE**（`create_publisher(..., 10)`）；用 `qos_profile_sensor_data`（BEST_EFFORT）时 web_video_server 的 RELIABLE 订阅收不到，页面只会转圈 |
| 泊车冲过头 | `/control/parking_state` 里的距离 | 减 `approach_speed`，调大 `target_distance`；深度不可靠时 `use_depth:=false` 改高度比 |
| 泊车原地转圈找码 | 码不在相机视野 | `search_speed` 降到 0.25；或先手动摆正车头 |
| 导航开始后车一顿一顿 | 是否有多个节点在发 `/cmd_vel` | 确认是本次版本（仲裁器会看 `/control/nav_active`）；关掉厂家 `simple_follower_ros2`；`ros2 topic info /cmd_vel -v` 看发布者个数 |
| 曝光调了没效果 | `/lighting/status` 的 backend | 实车 Astra 用厂家曝光，把 `exposure_backend` 设 `none` |
| OCR 全是乱码 | `ocr_debug_image` 是否清晰 | 文字太小/太斜；调 `scale`、`psm`（单行用 7） |
| `colcon build` 找不到 cv2/pyzbar | `python3 -c "import cv2"` | 离线源里补装 `python3-opencv python3-pyzbar libzbar0` |
