# 实车联调手册（完全离线可用）

> 面向：在**无网络**的场地上，从冷车开始把 ④⑤⑥⑦⑨⑪⑫⑬⑭ 一项项跑通。
> 车：WHEELTEC RDK X5，Ubuntu 22.04 + ROS 2 Humble，IP `192.168.0.100`。
> 本文所有命令都已在车上核对过**话题名和类型**，可直接复制粘贴。
> 最后更新：2026-11-25

---

## 0. 一页速查（熟手只看这个）

```bash
# 车上/SSH 每个新终端先跑这三行（建议存成 ~/rosenv.sh）
source /opt/ros/humble/setup.bash
source ~/wheeltec_ros2/install/setup.bash
source ~/smartcar_ws/install/setup.bash

# 终端1：校时 + 出厂底盘/雷达/相机
sudo date -s "2026-11-25 09:00:00"
ros2 launch turn_on_wheeltec_robot wheeltec_sensors.launch.py
# 终端1b（本车必跑）：彩色流兜底（出厂 OpenNI 彩色无帧）
ros2 launch smartcar_bringup color_usbcam.launch.py

# 终端2：我们的上层（浏览器看 HUD 时加 start_web_video:=true）
ros2 launch smartcar_bringup bringup.launch.py start_web_video:=true

# 终端3：发任务（二维码也会自动触发）
ros2 topic pub --once /mission/start std_msgs/msg/String "{data: door_3}"
ros2 topic echo /mission/status
```

**三条铁律**

1. 全车只能有一个 `/cmd_vel` 发布者：**跑我们的上层时，绝不能同时开 `wheeltec_keyboard` 和出厂 `simple_follower_ros2`**。
2. `bringup.launch.py` 只起上层节点，**不会**替你起底盘/相机/雷达，必须先跑终端1。
3. 急停：键盘遥控时按**空格**；没有遥控时 `ros2 topic pub --once /control/avoid_stop std_msgs/msg/Bool "{data: true}"` 让仲裁器立刻归零。

## 1. 开机与连接（无网）

1. 车通电，等约 45 s 让它自启完（`ping 192.168.0.100` 通）。
2. 电脑连车的 WiFi 热点（`WHEELTEC_xxxx`），或网线直连车上的网口。
3. 连接方式任选：
   - **VNC**：电脑 VNC 客户端连 `192.168.0.100:5900`，直接在车桌面开终端（最省事）；
   - **SSH**：`ssh wheeltec@192.168.0.100`（或 `ssh root@192.168.0.100`）。
4. 无网环境**不能** `apt`/`pip`；车上依赖已经装齐（pyzbar、tesseract、cv2、cv_bridge 等），不要重装。

> 车钟停在 2000-01-01 不影响话题通信，但会影响建图保存/日志时间，**每次开机都先校时**（第 2 节）。

## 3. 终端1：出厂传感器栈（底盘 + 雷达 + 相机）

```bash
ros2 launch turn_on_wheeltec_robot wheeltec_sensors.launch.py
```

这条 launch 一次起齐四样东西（以下话题名/频率均在车上实测；彩色流问题见本节末尾）：

| 设备 | 话题 | 频率 | 备注 |
|---|---|---|---|
| 底盘 | `/odom`、`/odometry/filtered` | 20 Hz | 收到 `/cmd_vel` 才动 |
| 乐动雷达 Lsn10p | `/scan` | 10 Hz | `/dev/wheeltec_lidar` |
| Astra 深度 | `/camera/depth/image_raw` | ~30 Hz | `16UC1`，单位 mm，**正交/无畸变** |
| Astra 彩色 | `/camera/color/image_raw` | ~30 Hz | 本车 OpenNI 彩色无帧，**用 `color_usbcam.launch.py` 兜底**（见本节末尾） |

**逐个自检（终端3，等 launch 打满 30 s 再执行）**

```bash
ros2 topic hz /scan
ros2 topic hz /odom
ros2 topic hz /camera/depth/image_raw
ros2 topic hz /camera/color/image_raw
```

通过标准：前三条分别出 `average rate: ~10`、`~20`、`~30`。

- 如果 `hz` 一直不出数字、但 `ros2 topic list` 里话题在：先停掉它，**重启车（断电再上电）**，再按本节从头来。反复 `kill` ROS 进程会把 FastDDS 的共享内存段弄脏，表现为“话题都在、一个字节收不到”。
- **彩色流没有帧**（雷达/深度正常）：本车（Astra Pro）已知问题——出厂相机 launch
  用的是 Astra_S 配置，OpenNI 那条彩色流在本车经常一帧都不出，但 **UVC 彩色设备
  本身是好的**（`v4l2-ctl -d /dev/video2 --stream-mmap` 能抓到帧）。
  2026-11-25 实测：断电重启**不能**恢复。**直接用下面的兜底方案，别折腾重启**。

  **终端1b：彩色流兜底（usb_cam 直读 UVC）**

  ```bash
  ros2 launch smartcar_bringup color_usbcam.launch.py
  ```

  它用 usb_cam + `pixel_format:=yuyv` 往 `/camera/color/image_raw` 发 640×480@~28 Hz，
  深度仍由出厂 astra 节点提供，下游节点（vision_detect/hud/parking/ocr/lighting）零改动。
  实测彩色 27~28 Hz，视觉链路（`/perception/line`、`/perception/debug_image`、
  `/hud/image`、网页流）全部正常。

  注意：
  - **只能有一份 usb_cam 占用 `/dev/video2`**。重复启动会
    `terminate called after throwing an instance of 'char*'`、
    `process has died ... exit code -6`；而且重复启动还可能把**正在跑的那份**
    一起弄死（表现为“进程还在但不出帧”）。正确做法是先清再起：
    ```bash
    pkill -f 'lib/usb_cam/usb_cam_nod[e]' ; sleep 2
    ros2 launch smartcar_bringup color_usbcam.launch.py
    ```
  - 别用 `pixel_format:=mjpeg2rgb`（本机 swscale 转色直接 Abort）；
  - 设备号不对时：`v4l2-ctl --list-devices` 找 "Astra Pro HD Camera" 的 `/dev/videoN`，
    然后 `ros2 launch smartcar_bringup color_usbcam.launch.py video_device:=/dev/videoN`；
  - 兜底节点和出厂相机节点会各有 1 个 `/camera/color/image_raw` 发布者，
    出厂那个本来就不出帧，不影响使用。

  **验证数据是否有**（在普通 wheeltec 终端里跑，`ros2 topic hz` 出 ~28 才算有帧）：

  ```bash
  ros2 topic hz /camera/color/image_raw
  ```

**测底盘能不能动（可选，10 秒）**

```bash
# 终端3（此时必须没有别的 /cmd_vel 发布者）
ros2 run wheeltec_robot_keyboard wheeltec_keyboard   # 方向键移动，空格=急停，k=退出
```

测完 **Ctrl-C 退出遥控**，再进入下一节。

## 5. ⑫ 巡线（最容易先跑通）

**准备**：地上贴黑线（白底黑线 `invert=false`；黑底白线改 `true`），把车摆在线上、车头朝线的方向。

```bash
# 终端3：看视觉输出（-1~1，正=线在画面右侧；丢线为 nan）
ros2 topic echo /perception/line
# 使能巡线（bringup 默认已开，发一次保险）
ros2 topic pub --once /control/line_enable std_msgs/msg/Bool "{data: true}"
# 看仲裁器最终输出（真正发给底盘的速度）
ros2 topic echo /cmd_vel
```

**通过标准**：车沿黑线走、能过弯、出界会自己找回；`/perception/line` 的符号与车的转向一致（线在右边，车右转）。

**不过怎么调**（改完不用重启，直接 `ros2 param set`）：

| 现象 | 处理 |
|---|---|
| 线根本识别不到 | `ros2 topic echo /perception/debug_image` 看二值图（VNC 里 `rqt_image_view`）；调 `/vision_detect threshold`（默认 100）或 `invert` |
| 车往反方向打舵 | `ros2 param set /line_follower kp -1.2`，或把 `invert` 反过来 |
| 抖/画龙 | 降 `kp`（1.2→0.8），或降 `target_speed`（0.25→0.15） |
| 转弯冲出去 | 降 `target_speed`、升 `max_angular`（1.5） |

停车：`ros2 topic pub --once /control/line_enable std_msgs/msg/Bool "{data: false}"`。

## 6. ⑪ 雷达 + 深度避障

**准备**：车静止或低速巡线中。人站在车侧后方。

```bash
ros2 topic echo /control/avoid_state      # NORMAL / SLOW / STOP
ros2 topic echo /control/avoid_stop
ros2 topic echo /perception/obstacle_distance
```

**测试**：手或纸箱正前方 1 m 处晃入 → 应依次出现 `SLOW`（<0.85 m）→ `STOP`（<0.35 m），且 `/cmd_vel` 归零；挪开恢复。

**注意**：深度只取画面上部 ROI（避免把地面当障碍），如果总是误停：调 `/obstacle_avoider depth_y_min/depth_y_max`（0.35~0.65）；雷达误报调 `forward_half_deg`（30°）。

## 7. ④ 二维码多信息解析

**准备**：打印样张（电脑上跑过 `python tools/make_qr_samples.py`），贴/立在车前 0.5~1.5 m，**不要斜得太多**（程序会补转 ±10/20/30/45°，但正面最快）。

```bash
ros2 topic echo /perception/qr_payload    # JSON：order_id/consignee/destination…
ros2 topic echo /perception/qr_valid      # true 表示字段齐全、可用
```

**通过标准**：出现 JSON，字段齐全时 `qr_valid=true`；同一个码 1.5 s 内不重复刷屏（`qr_repeat_sec`）。

**不过怎么调**：斜码读不出 → 先正对拍；`ros2 param set /vision_detect qr_interval 0.3` 提高尝试频率；纯文本码被拒 → `qr_allow_plain_text` 默认就是 true，检查是不是 `qr_required_fields` 不满足。

## 8. ⑨ 二维码引导泊车

`bringup` 里泊车默认 `auto_enable=false`（防误动），两种触发方式：

**手动**（推荐先这样标定）：

```bash
ros2 topic pub --once /control/parking_enable std_msgs/msg/Bool "{data: true}"
ros2 topic echo /control/parking_state       # SEARCH→ALIGN→APPROACH→HOLD→DONE
ros2 topic echo /control/parking_active      # true 期间仲裁器只认泊车
ros2 topic echo /cmd_vel_park
```

**任务触发**：`/mission/start` 或扫到合格二维码（`auto_start_from_qr: true`）。

**通过标准**：车对准码 → 前进 → 在设定距离停稳 1.5 s → `DONE`，`/mission/parked=true`。

**标定 target_distance（有深度，最准）**：

1. 手动把车推到你想停的位置（比如离码 0.45 m），让码在画面里；
2. 读实时测距（`distance` 是深度测出的米数，`height_ratio` 是码高占比）：
   ```bash
   ros2 topic echo /control/parking_state
   ```
3. 把 `distance` 的实测值写进
   `~/smartcar_ws/src/smartcar_bringup/config/params.yaml` 的
   `parking.target_distance`，重启上层栈；没有深度时改用 `height_ratio` 标定
   `parking.target_height_ratio`。

**没有深度数据时的备选**：调 `target_height_ratio`（码高占画面比例，默认 0.28，越大停得越近）。

**注意**：超时 35 s 会 `FAILED`；场地上先摆近一点（1.2~1.5 m）再测。

## 9. ⑤ OCR 文字识别

**准备**：A4 纸打印大字（中文/英文都行），贴在车门/门牌位置，占画面中间区域。

```bash
ros2 topic echo /perception/ocr_text        # 识别出的文字
ros2 topic echo /perception/ocr_status      # JSON：置信度/耗时/是否触发
ros2 topic pub --once /perception/ocr_request std_msgs/msg/Bool "{data: true}"   # 手动触发一次
```

默认每 2 s 周期识别一次（`trigger_mode: both`）。识别不出时：

- 文字太小/太糊 → 靠近到 0.5~1 m，或调 `ocr_reader scale`（1.5→2.0）；
- 背景花 → 调 `method`（otsu ↔ adaptive）；只想英文把 `lang` 改 `eng`（更快）。

## 10. ⑥⑦ 光照识别 + 曝光自适应

```bash
ros2 topic echo /camera/brightness     # 0=暗 1=中 2=亮
ros2 topic echo /lighting/status       # JSON：亮度均值/档位/当前曝光/后端
```

**测试**：手遮镜头 → 档位变 0；手机手电照镜头 → 变 2；撤掉回到 1。`/lighting/status` 里的 `luma` 和 `exposure` 应跟着变。

**Astra 相机注意**：`params.yaml` 默认 `exposure_backend: v4l2`（直接调 UVC 彩色设备）。如果调曝光时报错或彩色流被搞挂，改成：

```bash
ros2 param set /lighting_adaptor exposure_backend none    # 只识别亮度，不动曝光
```

演示 ⑥ 用 `none` 完全够（亮度档位照常输出）。

## 11. ⑬ 建图 → 录航点 → nav2 导航

### 11.1 建图（如果现成地图够用可跳过；已有 `WHEELTEC.pgm`）

```bash

```

### 11.2 录航点

```bash
# 终端2：nav2（AMCL 定位）
ros2 launch wheeltec_robot_nav2 wheeltec_nav2.launch.py
# 终端3：遥控到投递点，然后记录（每到一个点发一次名字）
ros2 run waypoint_nav record_waypoint --ros-args \
  -p waypoints_file:=$HOME/smartcar_ws/src/smartcar_bringup/config/waypoints.yaml
ros2 topic pub --once /mission/record_waypoint std_msgs/msg/String "{data: dock_3}"
```

录完把 `waypoints.yaml` 里的 `routes` 顺序按现场改好（`destinations.yaml` 负责 `door_3 → deliver_3` 的别名映射）。**录制器会重写文件、丢注释，先备份。**

### 11.3 导航验证

```bash
ros2 launch smartcar_bringup bringup.launch.py start_web_video:=true
ros2 topic pub --once /mission/start std_msgs/msg/String "{data: door_3}"
ros2 topic echo /mission/state       # NAVIGATING → DOCKING → DONE
ros2 topic echo /mission/nav_feedback
```

导航期间 nav2 自己发 `/cmd_vel`，仲裁器收到 `/control/nav_active=true` 会**自动让位**（这是设计，不是 bug），导航结束再接管回巡线/泊车。

## 13. 整车演示流程（建议录视频的顺序）

1. 冷启动 → 校时 → 起传感器栈 → 自检 4 个 `hz`（§3）。
2. 起上层 `bringup.launch.py start_web_video:=true`，打开 HUD 网页（§4）。
3. ⑫ 巡线 20 s（§5）→ 停车。
4. ⑪ 手挡车头，`STOP` 出现（§6）。
5. ④ 举二维码到车前，`qr_payload` 出 JSON（§7）。
6. ⑨ 发 `/mission/start`（或直接扫 ④ 的码）看 SEARCH→…→DONE（§8）。
7. ⑤ OCR 拍门牌（§9）；⑥⑦ 遮/照镜头（§10）。
8. ⑬ 发一条 `home` 或 `door_3` 路线，车自己开回/开到点（§11）。
9. ⑭ 起仿真循环录 30 s（§12，先停实车栈）。

## 14. 停机顺序（避免下次开机“话题都在但没数据”）

1. 终端3 停车：`/control/line_enable false` + `/control/avoid_stop true`
2. 终端2：Ctrl-C 停上层
3. 终端1：Ctrl-C 停传感器栈
4. 需要彻底干净时：
   ```bash
   pkill -TERM -f 'ros2 launch|vision_node|hud_node|web_video_server' ; sleep 3
   sudo rm -f /dev/shm/fastrtps_*      # 只在所有 ROS 进程都停掉后执行
   ```
5. 断电。

## 15. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `ros2 topic hz` 不出数、`topic list` 有话题 | FastDDS 共享内存脏了：全停 ROS → `sudo rm -f /dev/shm/fastrtps_*` → 重启；还不行就断电重启 |
| 彩色流无帧，深度/雷达正常 | 本车已知问题，**直接 `ros2 launch smartcar_bringup color_usbcam.launch.py`**（§3），断电重启没用 |
| `color_usbcam` 启动即 `exit code -6` / `Abort` | `/dev/video2` 已被别的 usb_cam 占用：`pkill -f 'lib/usb_cam/usb_cam_nod[e]'` 后重起，同一设备只能一份 |
| `ros2 topic hz` 什么都不输出但话题存在 | 别用 root 跑 CLI：在 `wheeltec` 终端里跑；root 下 FastDDS 跨用户共享内存会拿不到数据 |
| 车不动，`/cmd_vel` 有数据 | 检查是否有出厂 `simple_follower_ros2` 也在发 `/cmd_vel`：`ros2 node list \| grep -i follow`，有就 Ctrl-C 停掉 |
| 车乱动/两个“司机” | `wheeltec_keyboard` 和我们的仲裁器同时开；只留一个 |
| 浏览器 HUD 一直转圈 | `curl -s -m5 'http://127.0.0.1:8080/stream?topic=/hud/image' \| wc -c`，小于几万字节说明没帧；先查彩色流 |
| 终端中文乱码 | 车端日志是 GBK：`cat xxx.log \| iconv -f gbk -t utf-8`；电脑端控制台乱码不影响数据 |
| 改了 `params.yaml` 没生效 | 参数是启动时读的，重启对应 launch；临时调参用 `ros2 param set` |
| 斜 30° 的二维码读不出 | 正对放；程序已有 `qr_retry_angles` 补转，但仍以正面最稳 |
| 建图/导航时间戳告警 | 没校时，§2 |
| 相机一调曝光就掉线 | `ros2 param set /lighting_adaptor exposure_backend none`（§10） |

## 16. 参数文件在哪

- 全局参数：`~/smartcar_ws/src/smartcar_bringup/config/params.yaml`
- 仿真专用覆盖：`~/smartcar_ws/src/smartcar_bringup/config/params_sim.yaml`
- 路线/航点：`config/waypoints.yaml`、`config/destinations.yaml`

`--symlink-install` 下改 `src/` 里的参数文件，**重启 launch 即生效**；如果新增了文件，需要先 `colcon build --symlink-install` 或手动软链到 `install/.../share/`。
