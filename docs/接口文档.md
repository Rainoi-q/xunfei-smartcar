## 三、二维码 JSON 约定（功能④）

一条二维码需包含下列**必填**字段，缺任一个则 `/perception/qr_valid=false` 不发布：

```json
{
  "order_id": "A03",
  "consignee": "zhang_san",
  "destination": "door_3",
  "priority": 2,
  "weight_kg": 1.5
}
```

| 字段 | 必填 | 用途 |
|---|---|---|
| `order_id` | 是 | 订单号，进 `/mission/event`，PPT 展示 |
| `consignee` | 是 | 收件人 |
| `destination` | 是 | 目的地，经 `config/destinations.yaml` 映射到路线名 |
| `priority` | 否 | 订单优先级（保留） |
| `weight_kg` | 否 | 重量（保留，配合⑧以后做） |

- 必填字段由 `params.yaml` → `vision_detect.qr_required_fields` 配置；
- 纯文本二维码（`qr_allow_plain_text: true`）也接受，内容整体当作 `destination`；
- 解析后统一重新序列化为 JSON 再发布（字段顺序固定，方便测试/同屏展示）。

## 四、状态机约定（mission_manager）

```
IDLE ──二维码/手动──> NAVIGATING ──nav_done(true)──> DOCKING ──parked(true)──> DONE
                            │                          │
                            └──── 失败 / 超时 ──────────┴──> FAILED
任意状态 ──/mission/reset──> IDLE
```

`skip_navigation=true`（仿真）时 `IDLE → DOCKING` 直接跳过导航。

各阶段与速度出口的关系：

| state | `/cmd_vel` 来源 | 巡线 | 泊车 |
|---|---|---|---|
| IDLE | 仲裁器（巡线） | 开 | 关 |
| NAVIGATING | **nav2 直接发**（仲裁器静默） | 关 | 关 |
| DOCKING | 仲裁器（泊车，经 `/cmd_vel_park`） | 关 | 开 |
| DONE / FAILED | 仲裁器输出 0 | 关 | 关 |

`/mission/state` 纯文本示例：

```
IDLE
NAVIGATING deliver_3
DOCKING deliver_3
DONE
```

## 六、调试 HUD 约定

`/hud/image` 上的信息（英文 ASCII，避免 OpenCV 字体问题）：

```
XUNFEI CUP 2026  SMART CAR         T+012.3s
MISSION: NAVIGATING deliver_3
QR: order A03 -> door_3
LINE off +0.12   V +0.20  W -0.05
OBSTACLE CLEAR 1.35m   PARK --   MODE line
```

中文（收件人、OCR 中文）在 HUD 上显示为 `?`，视频剪辑时加中文字幕；
`/perception/qr_payload`、`/mission/event` 里是完整中文 JSON，截图作证据。
